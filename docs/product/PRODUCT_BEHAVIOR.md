# 用户可见行为

文档用途：说明普通用户实际看到的页面、可执行的操作和结果。
面向读者：订阅用户、产品审阅者和客服维护者。
文档状态：当前行为说明；更新时间：2026-09-02。
本文从用户角度描述当前系统，不作为内部 API 或数据库设计文档。

## 订阅和邮箱验证

1. 用户在订阅页输入邮箱并提交。
2. 系统发送一封验证邮件；邮件包含一次性验证按钮和 6 位验证码。
3. 用户可以在常用浏览器输入验证码，也可以打开邮件链接后点击“确认验证并进入门户”。
4. 验证成功后，当前浏览器获得门户会话，并可以进入 `/portal`。
5. 邮箱未验证完成时，系统不会把订阅视为可推送用户。

邮件地址会在浏览器本地作为“记住邮箱”的输入偏好保存，但不会保存门户登录 token。

## 已验证用户登录

已验证用户在订阅页输入邮箱并点击“已注册用户邮箱登录”，系统发送一次性登录邮件和 6 位验证码。打开邮件链接后还需要点击“确认登录并进入门户”；链接和验证码都有时效，成功使用后不能重复使用；知道邮箱地址本身不能直接进入门户。

如果用户在另一台设备完成验证，原设备可在桥接票据有效期内看到状态，并点击按钮领取当前会话。桥接票据不能替代邮箱验证，也不能重复领取。

## 门户

门户根据当前会话展示：

- 当前仍可能报名或关注的课程；
- 课程时间、校区、地点、签到方式和剩余名额；
- 最近推送通知时间线；
- 已注册的选课提醒；
- 今日新增、未来 24 小时开抢和暂停状态。

用户可以修改课程类别、校区、自主签到偏好，标记首次引导已读，注册/查看课程提醒，暂停或恢复推送，退出当前设备会话，或取消订阅。

门户请求不接受 URL 或 JSON 中的邮箱作为身份凭据；退出后再次访问门户会得到未登录状态。

## 课程状态和筛选

- 报名开始前：课程可以在公开课程列表中出现，但不能视为当前可报名。
- 报名窗口内：只有仍有名额且符合筛选条件的课程会进入用户推送候选。
- 报名截止、课程结束或数据库标记过期：课程不再进入公开有效列表、普通用户推送或二维码公开关联。
- 自主签到：页面统一显示“自主签到”；识别“自主”和“自选”两类来源文字。
- 常规签到：显示“常规签到”，不会被“仅自主签到”偏好选中。

## 通知和提醒

用户级邮件通知按个人类别、校区、自主签到偏好、剩余名额和暂停状态筛选，并按事件去重。通知可能是即时提醒、近期摘要、从容摘要、每日摘要或已开选监控提醒；这些是内部调度策略，用户只需要关注邮件标题和课程时间。

用户点击课程邮件中的“提醒我选课”后，可以在选课开始前收到提醒。提醒会在邮件或 Telegram 通道至少一个启用且发送成功时标记完成；如果通道关闭或发送失败，会保留待处理状态。

## 二维码共享

- 二维码页面公开展示课程上下文和已审核的共享图片。
- 上传必须先在门户完成邮箱验证并保持登录；贡献者身份由当前会话自动确定。
- 只支持 PNG、JPEG/JPG、GIF、WEBP，默认单图不超过 5 MB；文件扩展名和实际图片格式必须一致。
- 新上传先进入待审核状态，不会立即出现在公开列表；管理员审核通过后才可公开。
- 课程结束后，二维码不会继续出现在公开列表，也不能通过图片地址读取。
- 公共页面只展示脱敏邮箱和贡献次数，不展示完整邮箱、服务器路径、原始文件名或审核字段。

## 取消订阅和暂停

用户可在门户中取消订阅；取消后 Cookie 会清除，后续普通推送不会再发送。课程邮件中的退订/暂停链接是独立的邮件操作入口，不会建立门户会话。

暂停推送只改变推送暂停时间，不会删除用户偏好；到期后推送自动恢复。恢复推送也可以在门户中手动完成。

## 管理后台

管理员通过 `/admin` 查看抓取健康、课程、配置、推送、选课日志和订阅用户，并可以触发抓取、调整筛选和推送开关、发送测试邮件、管理二维码审核和清理过期课程。管理员接口需要 Nginx Basic Auth，并且应用本身还会校验应用层管理员凭据。
