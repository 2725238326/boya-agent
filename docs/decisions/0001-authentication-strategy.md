# ADR 0001：使用邮箱一次性挑战建立门户会话

- 状态：已采用
- 日期：2026-09-02
- 相关代码：`web/app.py`、`src/models.py`、`src/push/email_push.py`

## 背景

旧入口可以把已注册邮箱或长期订阅 token 作为门户身份材料。只知道一个邮箱不等于拥有该邮箱，因此这种流程不能证明用户所有权；长期 token 同时承担登录、邮件操作和跨设备用途，泄露后的影响也不清楚。

## 决定

订阅和登录都通过邮箱发送短期、一次性链接和 6 位验证码。原始链接只出现在邮件 URL 中，数据库保存 SHA-256 摘要；验证码保存基于 `WEB_SECRET_KEY` 的 HMAC 摘要，并设置有效期和错误次数上限。成功消费后，服务才签发 `HttpOnly` 的 `portal_token` 会话 Cookie。

邮箱验证和登录页的 GET 只显示确认页，POST 才消费对应挑战，以降低邮件安全扫描器抢先使用链接的可能。跨设备 bridge ticket 只在验证完成后、短期内、一次性领取。

## 后果

- 登录请求对未知邮箱返回通用结果，减少邮箱枚举。
- 新字段通过增量迁移加入，不删除旧订阅字段；旧长期 token 不再能登录门户，但退订/暂停/提醒邮件动作仍暂时使用它们。
- 浏览器不再把门户 token 写入 `localStorage`；已有用户可能需要重新完成一次邮箱登录。
- 单进程内存冷却只能抑制同一进程内的重复请求，多实例限流仍是后续工作。
