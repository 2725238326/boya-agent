# ADR 0009：按观察更新课程，独立核对覆盖并持久化事件

日期：2026-10-25。状态：采纳为下一版设计；实现与生产切换尚未执行。

完整方案见 [SCRAPE_DESIGN.md](../architecture/SCRAPE_DESIGN.md)，实施顺序见 [SCRAPE_IMPLEMENTATION_PLAN.md](../project/SCRAPE_IMPLEMENTATION_PLAN.md)。本文不改变当前通道开关。

## 背景

用户核心任务是找课和接收退选补位。现有 quick 仍遍历全部列表并混入详情；完整覆盖样本相隔 137 秒，期间有分页重复与重建浏览器。翻页文本摘要含人数，末页只有人数变化可离线复现误判；该缺陷与生产全部失败之间的因果尚未完全确认。

现有完整性保护避免异常清空课程，但整轮完成后才入库使前面页面的有效名额也等待后续工作。outbox 已可靠保存待发送任务，课程更新、补位事件和新课缓冲尚未形成同一事务边界。15 秒触发无法证明逐课实际时效。

## 决定

1. 名额观察、发现、目录核对和详情为独立意图，共享一个有预算、可合并、具公平性的读取执行器；浏览器操作只有一个拥有者，不增加调度进程或并发登录。
2. 读取适配器输出带身份、来源、会话代次和实际时间的观察。字段值摘要与分页身份摘要分开；只有确认范围/字段有效的观察才能推进课程。
3. 单课可靠正向观察可以先提交；覆盖报告独立标记 verified/endpoint_checked/incomplete。缺页或未知总数不能用于误过期其他课程。
4. 课程投影、观察、业务事件、发送资格及到期任务在同一 SQLite 事务中写入；提交后唤醒通知协程，定时扫描补救丢失的唤醒。
5. 补位按可报名 episode 去重；容量增加或前后间隔过久不能一律称退选。新课预告独立于每日摘要；必要字段缺失等待补全但不能丢失资格。
6. 按每课名额观测时间和端到端指标验收。候选时效目标与能力档位绑定；没有经验证的定向读取能力时按全目录实际容量运行并公开降级。
7. 接口与旧表增量兼容，旧 course_id 和直达链接保留；通过旁观评估、基线建立和显式引擎切换逐批上线，不让双引擎同时驱动浏览器或发消息。

## 保留与变化

保留 Flask、Waitress、SQLite WAL、单进程调度、签名飞书与 outbox；保留旧的 scrape_courses_result 和管理员触发入口作为适配。新增模块按职责逐步提取，不一次性重写大文件。

改变的是提交与调度语义：失败轮次可含可靠观察，但不能被标为完整目录；因此不直接把现有失败 ScrapeOutcome.courses 填成部分列表交给旧调用方。v2 使用新观察契约，旧失败契约仍保持空列表，防止旧路径误清空或误推。

## 选择依据

| 备选 | 结论 |
| --- | --- |
| 缩短全量周期 | 无法消除串行长任务、重登录与后续页面等待，可能增加负载 |
| 多浏览器并发 | 当前主机和会话边界成本高，也不能消除事件原子性缺口 |
| 直接依赖只读 HTTP 接口 | 需真实能力证据，作为可选适配器，不作为方案前提 |
| 移除重复/空快照检查 | 牺牲已具备的数据保护，不采用 |
| 引入外部队列与多服务 | 暂无容量证据，先用现有 SQLite 和通知任务 |

## 代价与回退

需要增加观察/运行/事件记录、字段级时间、持久意图和新的通知 job_type，并维护旧/新接口兼容；需要控制审计增长，处理分页移动、迟到响应和运行资源。即使改造完成，短于观测间隔的名额仍可能无法捕捉，外部发送仍有至少一次语义的重复窗口。

每个实现批次通过固定样例和故障注入后独立部署。回退停止 v2 生产与领取新 job_type，保留新增表、旧数据和成功去重记录，切回旧引擎；不恢复旧 DB 覆盖新的用户/事件数据。邮件保持暂停，Telegram 等待网络，自动选课冻结。
