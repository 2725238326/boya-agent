# ADR 0007：学生课程卡片与 Telegram 运维分工

日期：2026-10-24。状态：已部署，飞书学生课程已启用；Telegram 运维按用户决定待网络打通启用。实际结果见 [本轮验收](../project/SCRAPE_CARDS_RELEASE_2026_10_24.md)。

用户明确飞书服务同学找课和接收退选补位；运维使用 Telegram。该决定替代 ADR 0006 中飞书承载采集告警/恢复的部分，其签名、固定 HTTPS、持久队列和数据保护决定继续有效。

飞书运行时只领取课程和按原全局开关控制的摘要任务，历史系统告警留作审计但不投递。配置工具及生产工作流禁止飞书告警开启；管理员 readiness 的 alerts_enabled 固定为 false，role 为 student_courses。卡片每门课一张，提供官方报名与对应课程详情两个 URL 按钮，不引入回调或自动报名。

课程新鲜度是发送条件之一。相同课程的新课按预告/开选分阶段去重，既有成功记录参与迁移；补位按一次满员后重新开放的观测去重，不把剩余人数作为永久事件身份。过期、被筛选或陈旧快照跳过，不根据旧名额制造“可报名”提示。

Telegram 运维有独立环境开关和 channel=telegram_ops，复用 outbox 的退避和租约，冷却/恢复独立持久化。已存在的 Telegram 课程用途开关不变。额外 systemd timer 在主应用外检查健康、采集时效和磁盘，正常时不发消息，异常达门槛和恢复时通知。

实质配置启用前从服务器探测对应通道；失败不激活。保持私有环境备份、运行代码/配置脚本内容一致验证及 worktree clean；控制工作流/文档更新不强制应用重启。有效进程策略和凭据相同且运维关闭时，仅同步无运行影响的配置，不重新探测或重启。实际变更保留串行重启、启动后真实采集和回退。GitHub 临时上游浏览器审计与日常生产诊断分开，不通过吞掉失败伪报审计成功。

限制：外部投递仍有至少一次重复窗口；自定义卡片是快照，不实时更新；本机 timer 无法在整机断网/断电时发消息；无可识别上游总数时不能承诺独立的全量计数证明。邮件专项与自动选课冻结保持原决策。
