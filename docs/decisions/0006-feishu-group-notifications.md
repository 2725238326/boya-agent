# ADR 0006：飞书群 Webhook 与独立用途开关

日期：2026-10-24。状态：已实现，本地验证，生产发布结果另记。

用户要求将已验证连通的测试群机器人全面接入，并明确课程沿用后台全局筛选。采用群自定义机器人及签名，不引入飞书应用、open_id 绑定或双向事件运行时。

告警、恢复与课程任务全部复用 SQLite outbox，独立 channel=feishu。环境变量两个布尔开关分别控制 alerts/courses；只领取当前启用用途的 job_type，关闭不会消耗重试。课程投递前复核生命周期和全局筛选，不把个人提醒或邮箱送到群。每日汇总继续受原全局每日任务开关控制。

课程幂等键按群 Webhook 的不可逆指纹、课程、事件和日期/余量构建，跨即时/缓冲/active_watch 的首次课程消息去重。一个课程一个任务，避免部分成功批次被整体重放。任务只保存群指纹，不保存 Webhook 或签名密钥；变更群后旧任务跳过。

系统告警使用 system:scrape 作为 outbox 必需的非空 course_ids 标记，payload 只包含故障编号、允许列表中的错误类别、次数和群指纹，禁止采集错误原文或用户数据。冷却和恢复编号读取已有 outbox，进程重启后可以恢复。恢复创建后不再发送未投递故障消息，告警过期后跳过。

Web 请求仅接受固定飞书 HTTPS 主机和 Webhook 路径，不继承代理，不跟随重定向；HMAC 的 key 为 timestamp + newline + secret、message 为空。速率在后台线程中以进程锁串行控制，约 54 次/分钟；每次传输只请求一次，后续重试由 outbox 有界退避。无需添加生产依赖。

生产凭据经本机受控文件送入 GitHub production Secrets。独立 workflow 先探测群，再私有备份/原子更新 .env，仅更改飞书配置，串行重启并确认实际进程。失败恢复旧环境；常规代码部署和通知启用保持不同步骤，邮件等通道不随飞书启用。

不修改数据库结构，不增加公开发送 API 或前端凭据字段。残余限制为外部至少一次投递窗口、相同 webhook 下共享管理员/课程群、个人私聊及回调不支持，以及所有 HTTP socket 步骤的整体总耗时不保证严格等于 timeout 参数。
