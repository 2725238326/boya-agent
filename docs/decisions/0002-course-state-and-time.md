# ADR 0002：集中课程判断并固定业务时区

- 状态：已采用
- 日期：2026-09-02
- 相关代码：`src/course_state.py`、`src/time_utils.py`、`src/filters.py`、`src/scheduler.py`

## 背景

筛选、门户、推送、RSS 和二维码都需要判断签到方式、报名窗口、课程结束和热门程度。多个模块各自比较时间或搜索文字，会造成同一课程在页面可见、邮件可发和二维码可用性之间不一致。服务器默认时区也不应决定业务结果。

## 决定

`src/course_state.py` 作为课程业务判断的唯一实现，提供自主签到、报名开放、课程过期和热门课程判断。`src/time_utils.py` 使用 `APP_TIMEZONE`，默认 `Asia/Shanghai`；数据库继续保存兼容旧字段的 naive 时间，读取时按业务时区解释；RSS/Atom 的发布时间转成 UTC。

课程满足显式 `expired`、课程结束时间已到或报名结束时间已到任一条件时，都视为过期；报名开始时间未到时不可报名；边界由测试固定。自动选课、用户筛选、通知、RSS 和二维码都复用这些函数。

## 后果

- 新业务判断必须添加到共享模块并补测试，不能在 route 或推送函数中另写一套。
- 旧数据库时间不会被批量改写；如果历史数据实际采用了不同语义，需要在生产数据审计中确认。
- 用户页面和日志使用业务时间，RSS/Atom 遵循 UTC 标准发布时间。
