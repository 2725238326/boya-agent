# ADR 0008：当前文档、架构检查与服务器目录维护

日期：2026-10-24。状态：接受；实际执行结果记录在独立维护验收中。

## 问题

状态页不断追加发布快照，多个“当前”“下一阶段”互相冲突；架构和目录说明仍停留在旧通知分工和预发布计划。服务器有应用代码、真实配置、DB、上传、依赖、浏览器和调试产物，生命周期不同，不能用通用清理规则混合处理。

## 决策

1. 当前状态和待办各保留一份简洁主文档，整理前原文进入 archive；带日期发布证据保持原观察窗口和链接。当前操作文档指向状态页，旧方案明确标记历史。
2. 标准库 AST 检查核心依赖：领域规则不导入基础设施，数据/outbox/推送不反向依赖调度器和抓取器，src 除进程入口外不依赖 Web。当前 Markdown 本地链接和已跟踪运行文件也进入统一验证。
3. 生产维护工具默认只盘点，从已审阅 Git 对象提取执行，保持应用 SHA、工作树、PID 和健康。与发布和通知配置共享互斥组。
4. 自动化归档只面向 logs 根下七天前的独立捕获文件，要求新鲜清单、文件身份复核、同文件系统、写前恢复清单和摘要。其他状态只盘点，数据库/配置/上传/依赖/浏览器不自动搬动。

## 影响与回退

不改变当前运行配置和业务入口，不增加生产依赖。文档和维护工具提交不代表应用已部署。归档调整文件位置，不释放文件系统空间；永久删除或活跃路径迁移另需明确保留与恢复方案。

回退文档和检查可用 Git revert；归档按 manifest 校验后恢复，拒绝覆盖同名文件。旧状态和清单仍可追溯。检查只覆盖静态导入、当前文档文件链接和受控路径，不验证远端 URL、历史正文、动态依赖或长期稳定性。

操作入口见 [目录维护](../operations/DIRECTORY_MAINTENANCE.md)。
