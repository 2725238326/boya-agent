## 优先级定义

- **P0**：可能造成数据错误、重复/丢失通知、权限问题或无法安全上线。
- **P1**：明显影响可靠性、性能、用户完成任务的效率或日常维护。
- **P2**：文档、目录、文字和长期维护优化，不应阻塞核心业务修复。

## 当前明确不扩大的范围

以下内容不是本清单的下一阶段目标：

- 更换数据库或 Web 框架；
- 引入 Redis、Celery、Kubernetes 或微服务；
- 强行迁移 React、Vite 或复杂前端构建链；
- 一次性移动所有目录或重写所有大文件；
- 跨重启保存校园登录态；
- 将自动选课变成默认核心能力；
- 删除旧字段、旧 URL 或用途未确认的数据。

这些范围以后是否调整，需要新的需求、收益、风险、成本和回滚评估，不能因为“技术上可行”就自动进入实施。

## 新版本候选执行顺序

本批次按以下顺序推进，不在生产环境交叉执行未审阅的改动：

1. 更新文档状态，确认代码、配置和目录变更范围；
2. 在功能分支运行统一发布验证入口，保留完整输出；
3. 将代码、测试、文档和 CI 改动拆成可独立审阅的 Git 提交；
4. 核对远端功能分支和服务器工作树，服务器只做提交核对，不重启生产服务；
5. 完成门户窄屏、键盘、空状态、筛选和刷新检查；
6. 在邮件窗口和课程周期允许时，另行执行生产发布与真实业务观察；
7. 根据观察结果再决定是否迁移更多通知路径、扩大 TypeScript 7 范围或拆分模块。

候选版本的准入条件、用户场景和回退依据见 [RELEASE_CANDIDATE.md](RELEASE_CANDIDATE.md)。
