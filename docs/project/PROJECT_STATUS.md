## 项目用于什么

帮助北航同学发现合适的博雅课程，并在真实退选释放名额时收到补位提醒。公开网页负责查课、筛选和核对采集时间，飞书群负责课程卡片，报名由同学在官方系统完成。运维异常和恢复单独交给 Telegram。

## 已完成的可靠性工作

- 采集区分有课、无课、认证失效、上游故障、解析失败和超时；异常快照不覆盖可靠数据。
- 翻页验证完整表内容、首页/末页边界与重复页面。生产曾确认 7 页、131 条原始唯一记录；上游没有独立总数，仍需观察页面结构变化。
- 签到标签只看签到字段；缺失值显示“待确认”。名额使用最新完整容量/人数，陈旧课程不进入新飞书推送。
- 通知使用 SQLite outbox、租约、去重和有限重试；外部渠道仍有至少一次投递的重复窗口。
- 预发布使用 fixture、独立数据库/日志/上传和文件邮件，阻断真实校园与通知连接。
- 生产发布有数据库/二维码备份、旧代码与必要 venv 恢复、健康检查和启动后真实采集检查。

本次维护增加模块依赖、当前文档链接和受控运行文件检查，统一目录用途；服务器已完成只读盘点和 4 份配置回退副本整理，步骤见 [目录维护](../operations/DIRECTORY_MAINTENANCE.md)，执行证据见 [维护验收](MAINTENANCE_2026_10_25.md)。

## 剩余事项

1. **分页重试根因**：复现现场交替成功与重复页/异常空结果，保留快照保护，补回归后单独修复发布。
2. **Telegram 运维网络**：取得可用网络或代理后，再验证真实消息与独立 watchdog；目前保持关闭。
3. **真实邮箱验收**：验证 SMTP、SPF/DKIM/DMARC、收件箱与垃圾箱、验证码/链接、暂停/退订，先开放身份邮件。
4. **持续观察**：SSO 波动、分页覆盖、历史陈旧行、Swap/磁盘及备份恢复。一次验收不能替代长期指标。
5. **后续代码拆分**：先按架构依赖保护规则形成小批次，再逐步拆分 `web/app.py`、`src/scheduler.py`、`src/scraper.py`，保留现有接口。
