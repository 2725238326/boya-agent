# 抓取架构实施与验收计划

日期：2026-10-25。状态：P1 代码已实现，正在验收；P2–P6 尚未实现。实际应用版本与发布结果见 [P1 执行记录](SCRAPE_P1_2026_10_25.md)，本文件不以实现代替上线结果。

设计依据：[完整方案](../architecture/SCRAPE_DESIGN.md)、[ADR 0009](../decisions/0009-observation-driven-scraping.md)、[实际通知需求](../product/NOTIFICATION_REQUIREMENTS.md)。设计起点为 `main@baddef4`；P1 从 `ce84f3d` 开始，执行事实单独记录，保留后续目标与当前实现的边界。

## 1. 逐批交付

| 批次 | 实现范围与交付物 | 上线前必须通过 | 现场通过条件 / 回退 |
| --- | --- | --- | --- |
| P1 分页与恢复止损 | 提取分页身份/值摘要；局部重读；按错误分级保留健康会话；记录阶段时间 | 末页人数变化、同页卡住、延迟渲染、数字页/旧控件、路由占位空状态；不得移除完整性保护 | 对比连续轮次身份/覆盖和失败原因；异常切回原分页策略并保留证据，不降低错误检查 |
| P2 读取能力与预算 | 验证 source_id/范围/排序/可解码只读响应；合并意图与单执行器；有界命令、逐课到期与公平性 | 无定向能力仍全目录发现；手动触发合并；full 不因 quick 被吞；超载和 429 降速；单 Page 操作互斥 | 输出能力档位、读取负载与有效时效基线；未达条件保留 browser_catalog，不能启用更强时效承诺 |
| P3 观察与原子事件 | 新契约、幂等增量迁移、名额/详情时钟、身份映射、投影/事件/资格/outbox 同事务 | 乱序/重复/字段未知/锁失败/进程终止；来源错误隔离；不完整覆盖不误过期 | 首次建立基线不广播现有课；核对旧成功去重；回退保留新表并停止新 job_type |
| P4 详情与发现分离 | 详情使用受控独立页、有界持久重试；新课资格不依赖每日摘要；目录读结果可满足多个意图 | 详情 30 秒超时不阻塞其他名额；失败字段可重试；历史已结束课不反复补详情；字段齐备后重评资格 | 页面/名额时效改善，发现周期不饿死；未确认签到等仍不得越过群筛选 |
| P5 通知与显示时效 | 提交后唤醒、5 秒补救扫描、补位优先、TTL/episode 发前复核；API/前端字段与缓存对齐 | 丢唤醒恢复；入队后满额/关闭/过期跳过；容量增加正确文案；旧/新任务不串领；时钟变化与缓存 | 使用授权测试群做最小探测，真实业务消息不因切换重发；异常关闭 v2 领取并保持采集 |
| P6 连续运行验收 | 管理摘要/日志、负载/磁盘/备份核对，逐课时效与失败分类，阶段性发布记录 | 1000 次确定时序 fixture；双 Python、浏览器、旧库、独立服务恢复 | 生产至少 72 小时并覆盖一个真实开选窗口；缺窗口则待验收；保留逐批 SHA/备份/开关/实际数据 |

每批只提取本批所需模块；先通过变更分支 CI，再按受控发布流程上线并核对真实采集。P1 不等待全部 v2 完成，可独立减小当前故障影响。P3 事务与 P5 发送处理器必须兼容落地，不能先打开 v2 事件生产再补处理器。

P2 的固定数据调度器可先离线开发；接入当前应用的生产行为切换，要在 P3/P4 合同和旧路径适配就绪后执行。批次顺序是依赖关系，不是六次强制生产重启。

## 2. 能力检查清单

所有检查优先使用已有正常读取的受控证据与离线样例；需要真实上游的检查只做只读小范围操作，使用服务器既有身份。

| 未知项 | 要取得的证据 | 未通过时的处理 |
| --- | --- | --- |
| 能否直接查询名额 | 同会话只读、可解码、身份/字段/窗口/授权一致，无写操作 | 保持 DOM 读取，不设计假接口 |
| 有无稳定上游课程键 | 修改地点/介绍不变 ID，并行场次不冲突 | 保留系统旧 ID，冲突待核对，禁止误合并/误新课 |
| 默认排序与筛选范围 | 明确排序和边界；课程分布变化仍能发现尾页新课 | 不能将只扫首页作为发现完成 |
| 页码/游标/总数 | 真实标记、控件行为、响应与请求绑定 | 使用端点核对，覆盖等级为 endpoint_checked |
| 详情返回是否改变列表页 | 固定样例与受控现场比较，返回页码/筛选可确认 | 详情用独立页或重定位复核；不能盲目继续下一页 |
| 可承受频率和耗时 | 每类命令耗时/响应码/逻辑读取率、逐课年龄与 CPU/内存 | 以更低总预算运行，明确降级，停止非必要详情 |

禁止为证明接口可用而调用报名、退选或管理写接口。不得在报告粘贴真实响应、Cookie、代理凭据或个人数据。

## 3. 回归与故障注入矩阵

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | 末页课程不变，仅人数变化 | 不认为进入下一页；名额值可更新；有端点证据才确认边界 |
| T02 | 下一页卡住但末页可以移动 | 不冒充完整覆盖；记录局部失败，无误清空 |
| T03 | 两页相同前缀、不同尾部；身份相同但值变化 | 身份摘要正确区分页，值变化不替代页移动 |
| T04 | 路由未落定/请求未完成时出现暂无课程 | 不判真实空目录，保留旧数据 |
| T05 | 第一页有新名额，第六页超时 | 第一页可靠观察提交；目录报告 incomplete；第六页旧数据不被删除 |
| T06 | 课程排序改变、页数变化、旧 checkpoint 恢复 | 重新校验范围/身份；不能用旧页码证明无遗漏 |
| T07 | 无活跃课程，尾页出现新课 | 发现意图仍运行且覆盖尾页；不等待已有课程开选才发现 |
| T08 | 热点持续存在，同时 full 与手动刷新到期 | 同范围合并、full 意图不丢、普通课不饿死、单浏览器拥有者 |
| T09 | 详情缺字段、暂时失败、返回列表改变位置 | 必要详情可重试且持久；其他名额不等待；列表状态复核 |
| T10 | 同批观察重复提交；旧响应晚到 | 唯一键防重，旧观察不覆盖新 seat_version |
| T11 | 用户表/旧课程/历史成功队列升级，重复初始化 | 旧 ID/数据/链接/成功去重保持，增量迁移幂等 |
| T12 | 事务中途 kill，或 DB busy/写满 | 状态、观察、事件和 outbox 要么全部提交要么全部回滚 |
| T13 | commit 后、唤醒前 kill | 重启扫描能找到已提交任务；不漏业务事件 |
| T14 | 外部服务接受后、成功落库前 kill | 明确保留至少一次语义；可能重复单列，不伪称 exactly-once |
| T15 | 同容量 20/20→19/20→18/20→20/20→19/20 | 两个补位 episode；中间普通人数变化不刷屏 |
| T16 | 容量增加、窗口未知、间隔过长后看到余量 | 不能统一称退选；未知窗口不发已开选补位 |
| T17 | 名额对缺一项、容量未知、负数/超额 | 不制造 0 或乐观余量；质量异常可追溯，禁止补位 |
| T18 | 入队后再满额、过期、被新 episode 取代 | 投递前跳过并保留具体 outcome，无过期补位追发 |
| T19 | 自主签到缺失，后来详情确认符合群筛选 | 等待资格可重评；不依赖新 ID、重启或每日摘要 |
| T20 | 超过一天的新课，daily_summary_enabled=false | 新课预告独立产生资格，不受已关闭摘要吞掉 |
| T21 | 确认 SSO 失效、普通解析错误、429 分别注入 | 仅认证问题登录；解析局部恢复；429 按依赖退避；无 driver 泄漏 |
| T22 | 墙上时钟回退、进程重启、会话代次变化 | monotonic 预算继续有效，迟到响应不混入新会话 |
| T23 | 请求预算耗尽、热点多到不可满足目标 | 不叠加扫描；记录所有未读/逾期课程，停止低优先详情并报告降级 |
| T24 | API/浏览器缓存、页面隐藏与重新可见 | 观察时间准确，缓存延迟有界；刷新网页不触发上游风暴 |
| T25 | v2→legacy→v2，存在旧成功/新待处理任务 | 单引擎单 driver；旧处理器不误领新类型；无全量重发 |
| T26 | 稳定观察长期运行与审计清理 | 观察增长受限，事件锚点受保护；清理不锁长事务、不删除业务数据 |
| T27 | 引擎切换后旧数据库线程才返回 | 持久 generation 检查拒绝旧引擎提交/生产任务；不依赖取消 Task 就当停止 |

P1 先覆盖 T01–T04 和浏览器生命周期；P2/P3 重点覆盖 T05–T13、T21–T23；P4/P5 覆盖事件和消息；T25–T27 在正式切换前完成。测试设计使用时钟与真实页面交互共同验证，不能只 mock 所有翻页方法后断言调用次数。

## 4. 性能验收方法

固定样例生成至少 1000 次有真值变化，包含短于巡检周期的名额、页尾课程、失败、繁忙和重启。输出 P50/P95/P99、分母、未知/超时/过期/漏观测计数；明确短暂机会无法全部捕捉，不移除失败样本美化。

样例按名额持续 5/15/30/60/120 秒分组，分别报告捕获率；对持续至少两倍该能力档位目标观测间隔、且未到截止的机会，候选发现率 ≥99%。更短机会单列漏观测率，不能把“采集读到后的交付率”当作“所有退选捕获率”。

旧链路与新链路使用同一组离线时序、上游服务时间与总读取预算比较。生产旁观阶段不增加第二套扫描或第二份消息；可旁观当前读取并比较身份/解析/事件候选，不能据此宣称已验证新调度性能。

| 层次 | 记录内容 |
| --- | --- |
| 单命令 | 排队、开始、请求完成、解析完成、提交；失败类型与 deadline |
| 每门课 | 名额观察年龄与间隔，未读/未知也进入统计；热点与非热点分开 |
| 发现与核对 | 范围、覆盖档位、实际新课发现延迟（fixture 真值）、报告年龄 |
| 通知 | 事件提交→开始投递→外部接受，失败/跳过/过期、可能重复 |
| 用户界面 | API 缓存、前端刷新、可见状态与显示观测时间 |
| 资源 | driver/浏览器/页面数、应用 RSS/cgroup、主机可用内存/Swap、逻辑读取率、DB/WAL/审计增长 |

候选数值目标见设计第 12 节；未取得定向能力证据时使用 DOM 全目录档位的目标。没有上游真实变更时间时，不报告“真实退选到群消息 P95”。

## 5. 发布、配置与恢复

1. 每批建立独立提交和 PR；保留当前通知边界，完成本地与双 Python CI、相关浏览器/故障演练。
2. 新配置字段先在统一解析器实现并测试；`.env.example` 属于部署触发路径，不提前把未实现参数写成可用配置。
3. P3 上线前在线备份 DB、二维码和私有配置，确认恢复方法；新表/索引幂等且旧代码可读取旧字段。
4. 新处理器先存在但不领取，observe 模式评估记录隔离；不得更改当前课程和既有 outbox，单浏览器执行器拥有权不变。
5. active 切换时暂停旧事件生产/缓冲与旧读取入口，保存切换水位；首次可靠观察只建 baseline，后续变化再生成新事件。既有成功阶段和目标哈希迁移去重。
6. 分别启用 v2 观察写入、资格评估、明确的新任务类型领取；中间状态有上限，不允许产生无人处理的补位积压。
7. 异常切回 legacy：取消/等待有界命令退出，关闭 v2 领取，保留新增数据；未发送事件按 TTL 过期。不能让旧引擎与新引擎同时触发读取/群推，也不倒灌过时缓冲。
8. 验收报告记录真实应用 SHA、模式/能力档位、旧/新配置范围、服务/DB/采集/通道证据与回退版本。Telegram 仍待网络，邮件暂停，自动选课冻结。

外部通道已经接受的消息无法通过 DB 回退撤销；紧急时首先停止新任务领取并保留数据。供应商在途请求存在边界窗口，开关关闭后不再开始新请求，已经发出的请求结果单独记录。

## 6. 设计交付与后续实现分界

本轮设计交付包括完整规格、ADR、实施与故障注入矩阵、可交互导览、文档导航和待办同步。检查文档链接与导览可用性只证明设计工件可读，不能算分页修复、低延迟目标、事件原子性或生产效果已验证。

实施没有依赖用户重新提供飞书凭据；当前服务器已有授权配置可沿受控流程使用。Telegram 网络与真实邮箱验收继续独立处理，不成为离线核心设计或实现的前置阻塞。

本轮工件验证：交互导览在 Chromium 的 1280px/390px 宽度检查四个页签、八个异常场景、键盘方向键/End 导航、无整页横向溢出或 JavaScript 错误；桌面与移动截图目视复核。文档本地链接与差异检查通过后提交。截图为设计页面，不是飞书客户端或生产系统截图；没有运行本表尚未实现的采集性能测试。
