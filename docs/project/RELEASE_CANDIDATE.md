## 变更范围

### 抓取与运行效率

- 用页面状态、课程行和明确的空状态作为等待条件，减少固定时长等待。
- 网络空闲等待改为有上限的辅助条件；页面状态仍由课程页面条件决定。
- 正常轮次默认不保存截图；发生异常时保留受控的 HTML 和错误截图，便于定位上游页面变化。
- 记录本轮抓取耗时，并通过管理员状态接口提供最近一次耗时。

### 门户体验

- 请求增加超时、取消和旧结果保护；重复初始化请求合并处理。
- 课程列表显示加载中、当前无课、筛选无结果和加载失败等不同状态，并提供对应操作。
- 刷新操作显示进行中状态，后台刷新查询使用逐步延长的查询间隔。
- 页签、筛选控件、状态区域和课程列表补充可访问性语义；支持键盘焦点提示和减少动画设置。

### 前端类型检查

- TypeScript 固定为 7.0.2。
- 首页、持久登录、二维码和订阅桥接脚本纳入类型检查；浏览器运行方式不变。
- 门户和管理台脚本暂不一次性纳入，避免用大范围类型改写掩盖行为风险。

### 工程与目录

- 根目录旧审计快照归档到 `docs/archive/legacy/`。
- 增加统一发布候选版本验证入口：`scripts/verify_release.py`。
- 增加功能分支 CI；生产部署工作流只接受 `main` 或 `master`，并保留生产环境审批配置位置。
- 工程标准、改进清单、状态文档和发布记录统一指向当前事实。

## 用户场景验收

候选版本至少应检查以下场景：

- 没有课程时，用户能理解这是当前课程池为空，而不是系统异常，并能刷新或打开官方选课页。
- 筛选条件没有结果时，用户能清除条件，不必重新登录。
- 课程接口失败或超时时，用户能看到明确提示和重新加载操作。
- 课程刷新进行中时，按钮不可重复提交，完成后能看到新的更新时间。
- 移动端能够完成查看、筛选、刷新、设置提醒和切换页签。
- 键盘操作能够识别当前焦点，状态变化能够被辅助技术读取。

## 回退依据

- 代码回退优先使用已审阅的 Git revert 提交。
- 数据库只执行可重复的增量迁移，不因代码回退删除新表或旧字段。
- 通知任务保留在数据库中；代码恢复后应继续处理可恢复任务，并核对是否存在重复投递窗口。
- 生产发布前必须记录上一版本提交和数据库备份位置。

## 未在本批次作出的承诺

- 未承诺真实课程周期之外的长期抓取稳定性。
- 未承诺 SMTP、Telegram 的长期可达性或绝对不重复投递。
- 未将门户和管理台全部脚本一次性改成 TypeScript。
- 未引入 Redis、Celery、Kubernetes、前端构建系统或多实例部署。
